record of what was installed lives.

`install` returns an `InstallResult`: each harness's parts with their states,
notes and warnings, as text (`to_text`) or JSON (serde).

A tool that should name no agent at all calls `follow` with a `Request`
(its name, a scope, its instructions) and prints the `Outcome`'s report,
exiting with its code (see
[Instructions](/agent-harness-adapter/write-once/instructions/#hand-them-over-and-name-no-harness)).

`keep_instructions(&tool, text, scope)` keeps a text your tool no longer
manages as the project's own (see
[Instructions](/agent-harness-adapter/write-once/instructions/#keep-a-tools-text-as-the-projects-own)),
and returns `Kept`, a report to print as it stands (`to_text`).

## Answer a hook

The hook command reads the harness's input as a `HookInput` and answers with
an `Answer`; `emit` writes it in the harness's form.

`hook::wire` gives Claude Code's input and reads Claude Code's answers, for
a command that speaks the contract itself.

## The config, from Rust

`manifest::Manifest` reads a manifest or the config
(`manifest::find_config`) and `manifest::ManifestTool` makes it a `Tool`, as
the command does.

This page's example is `crates/lib/agent-harness-adapter-core/examples/mytool.rs`;
CI builds and runs it.
